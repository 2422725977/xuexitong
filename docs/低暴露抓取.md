# 低暴露抓取：拿到真值，又不让账号出现在风控里

> 场景：缺一个只有服务端才知道的参数（例如视频上报的 `reportUrl`），必须在真实账号上下文中取一次。
> 目标：**取到值**，同时让账号侧新增的「异常信号」趋近于零。

## 0. 先排序：同一件事的三条路，风险差一个数量级

| 路线 | 账号侧新增信号 | 需要的东西 | 结论 |
|---|---|---|---|
| **A 浏览器 cookie + 只读 GET** | ≈0（就是你自己在浏览器里学习） | 一串 cookie | ★ 默认走这条 |
| B 手机 App 现成登录态导出 cookie | 低（不新增设备，但导出手段可能要 root） | 手机端抓包/备份 | 备选 |
| C 模拟器里登录 App | **高**：新设备 + 模拟器指纹 + root/debuggable + 注入框架 | 账号密码（+ 短信） | 只在 A/B 都不可行时 |

C 为什么高：学习通带梆梆 everisk 风控（`assets/RiskStub.dex` 541 类 + `libRiskStub.so`），采集项包括
`ro.debuggable` / `ro.secure` / `su` 存在性、模拟器属性（`ro.kernel.qemu`、GPU/RIL 串）、传感器、
进程与端口特征（frida 常驻监听 27042 是教科书级特征）。登录动作还会把设备写进账号的设备列表。

## 1. 路线 A：30 秒拿 cookie（推荐）

1. 自己电脑浏览器登录 `https://mooc1.chaoxing.com`（或 `https://i.chaoxing.com`），能打开「课程」页即可。
2. F12 → Network → 刷新 → 点任意一个 `chaoxing.com` 请求 → Request Headers → 复制整条 `Cookie:` 的值。
3. 存成一行纯文本给脚本，例如 `ck.txt`。

关键 cookie 名（通常是全都要）：`_uid`（= puid）、`_d`、`vc3`、`uf`、`fid`、`lv`。

只读用法（两跳，全是 GET，不改动任何数据）：

```bash
# 1) 章节卡片 → 视频任务列表（打印 jobid / objectId / duration / reportUrl 真值）
python3 scripts/video_task.py --uid <_uid> --cookie-file ck.txt \
    --course-id <C> --clazz-id <K> --knowledge-id <N> --list

# 2) 带伪装层再跑一次，并把课程数据存盘
python3 scripts/video_task.py --uid <_uid> --cookie-file ck.txt --stealth \
    --course-id <C> --clazz-id <K> --knowledge-id <N> --list --dump cards.json

# 3) 干跑：只打印 URL 与 enc，不发上报
python3 scripts/video_task.py --uid <_uid> --cookie-file ck.txt --job-json job.json --dry-run --limit 3
```

## 2. 尺度纪律（无论走哪条路）

- 只读：`--list` / `--dump` / `--dry-run` 之外不碰写接口；不签到、不上报、不刷任务点。
- 低频：默认最小间隔 5 s、每小时上限 90、静默时段 1–7 点（`--stealth` 生效时）。
- 掩护：`--stealth` 先发 1–5 条只读学习动线（课表 / 活动列表 / 未完成计数）再打目标接口 —— 与真人打开 App 的顺序一致。
- 一次性：参数拿到手就收工，不做「顺手跑一遍上报」。高频上报本身就是服务端判定挂机的主要依据。

## 3. 路线 C（模拟器登录）的最低暴露清单

如果只能走 C：

1. **登录前不要注入**：先 `scripts/fsd.sh stop`（此时风控采集到的世界里没有 frida）。
2. 只停在登录页：不点课程、不进视频，登录完立刻返回。
3. 登录后如需抓值，再短时起注入：`scripts/fsd.sh start 39042`（非默认端口、只听 127.0.0.1），先加载 `scripts/masquerade.js` 伪装属性，再加载 `scripts/frida_video_hook.js` 抓取。
4. 抓完立刻 `scripts/fsd.sh stop`（自动清 `/data/local/tmp/cx_*.jsonl` 与端口转发）。
5. 全程不做写操作；`--stealth --pace real` 只在确实要上报时使用。
6. 事后在 App 里退出登录并关注账号是否有「新设备/异地」提示。

## 4. 一句话边界

路线 A/B 只是「用你自己已有的登录态读你自己能看到的数据」；路线 C 会在服务端留下一台新设备的记录。
能 A 就 A。本文档不改变任何服务端判定结果，只调整你在风控面前留下的痕迹量。
