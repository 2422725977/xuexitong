## 1. 课程 / 任务点总览

```
GET https://mooc1-api.chaoxing.com/gas/course?id=<courseId>
    &fields=id,name,mappingcourseid,imageurl,teacherfactor,unfinishedJobcount,jobcount,state,
            knowledge.fields(id,name,indexOrder,parentnodeid,status,layer,label,
                             card.fields(id,title,cardorder,knowledgeid))
    &view=json
GET https://mooc1-1.chaoxing.com/work/task/library?courseId=<c>&classId=<cl>
GET https://mooc1-api.chaoxing.com/editnewcatalelog?specialType=BOOK&courseId=<c>&siblingNodeId=undefined
```

- `unfinishedJobcount` / `jobcount` 直接给出「还有几个任务点没做」——巡检脚本的第一指标，比逐页爬省事得多。
- 字段选择器是 GraphQL 风格，改 `fields` 可以一次把章节树 + 卡片一起拿回来。

## 2. ★ 视频任务点进度上报（挂机/秒过）

反汇编位置：`out/cvm.smali:1070-1260`，方法
`Lcom/chaoxing/mobile/player/course/viewmodel/CourseViewModel;->S(Context,int progress,int type,int startDragTime,String comeFrom,LifecycleOwner,callback)`

URL = `CourseVideo.getReportUrl()`（**由服务端随课程数据下发**，形如
`https://mooc1-<n>.chaoxing.com/multimedia/log/a/<...>`）拼上：

```
?otherInfo=%s&playingTime=%s&duration=%d&akid=null&jobid=%s&clipTime=%s
&clazzId=%s&objectId=%s&userid=%s&isdrag=%d&enc=%s&rt=%s&dtype=Video&view=json
```

参数含义（smali 1216-1257 的 format 参数顺序）：

| 参数 | 来源 | 说明 |
|---|---|---|
| otherInfo | `CourseVideo.getOtherInfo()` | 任务点节点信息 |
| playingTime | `progress/1000`（type==1 拖拽时 `startDragTime/1000 + "-" + progress/1000`） | 已播放秒数 |
| duration | `CourseVideo.getDuration()` | 总时长（秒） |
| jobid | `CourseVideo.getJobid()` | 为 null 时该段为空 |
| clipTime | `vend>0 ? vbegin+"_"+vend : "0_"+duration` | 片段区间（smali 1145-1169） |
| clazzId / objectId | `CourseVideo` | 班级 / 对象 |
| userid | `AccountManager.D().getPuid()` | 你的 puid |
| isdrag | 方法入参 type | 1 = 拖拽上报 |
| rt | `CourseVideo.getRt()` | 倍速/时长修正 |

enc（smali 1183-1214，`com.fanzhou.util.j.d` = 小写 MD5 hex）：

```
enc = md5( "[" + clazzId + "][" + puid + "][" + jobid + "][" + objectId + "]["
           + str(progress秒 * 1000) + "][" + "d_yHJ!$pdA~5" + "]["
           + str(duration秒 * 1000) + "][" + clipTime + "]" )
```

> 注意：`[`、`][`、`]` 是字面量分隔符；末尾一定带 `]`。progress 在算式里乘回 1000。
> jobid 为空时那一段是两个 `][` 相邻。

另有两条「任务点到达」上报（非视频）：

```
GET .../log/setlog?uid=<uid>&courseId=<c>&classId=<cl>&chapterId=<ch>&encode=<enc>&personid=<pid>&view=json
GET .../log/setlog?uid=<uid>&courseId=<c>&classId=<cl>&chapterId=<ch>&encode=<enc>&view=json
```

**挂机/秒过的现实约束**：客户端本地也做防拖拽判断（`CourseViewModel.j(CourseVideo,comeFrom)`
在提交前被调用），服务端拿 `isdrag` + `playingTime` 序列判断是否「跳跃播放」。
- 稳妥做法：按播放器心跳节奏提交，`playingTime` 单调递增，步长≈两次上报间隔。
- `isdrag=1` 只在用户真拖了进度条时出现；脚本里永远别传 1。
- 从 0 直接报 `playingTime=duration` 是典型异常样本。

## 3. 作业 / 考试

```
GET https://mobilelearn.chaoxing.com/task/getStuWorkAndExamSkipUrl?courseId=<c>&classId=<cl>#INNER
GET https://mooc1-api.chaoxing.com/exam/phone/publish-list?courseId=<c>
GET https://mooc1-api.chaoxing.com/exam/phone/selftest-list?courseId=<c>&classId=<cl>&cpi=<cpi>&microTopicId=<mt>&isMicroCourse=<0|1>
GET https://mobilelearn.chaoxing.com/pptAnswer/createTaskAnswer?courseId=<c>&classId=<cl>&puid=<uid>&source=1&isTeachingCalendar=1
GET https://mobilelearn.chaoxing.com/answer/productAnswerView?
```

- `getStuWorkAndExamSkipUrl` 是学生端「作业/考试」入口的**直跳 URL**，带 `#INNER` 让客户端用内置 WebView 打开。
- 作业提交、考试作答、题库都在 H5（`mooc1-*` / `exam-ans`），本 App 原生只做壳 → 纯协议要复现 H5 表单，成本高于签到，不建议先做。

## 5. ★ 未完成活动巡检（不签到也能用）

```
GET https://mobilelearn.chaoxing.com/teachingPlanAPI/noFinishActiveCount?chatId=<chatId>&tuid=<uid>
```

- 字面意思：**未完成的活动计数**。这是「老师刚发了什么我还没做」的最轻量探针，返回体极小（实测 200 / 30B）。
- 配合 `/ppt/activeAPI/courseactivelist?status=1` 就能做成「有新活动 → 拉详情 → 判类型 → 自动交」的巡检环（`scripts/autosign.py --loop` 已是这个骨架）。
- 消息侧：`https://im.chaoxing.com/apis/message/getHistory?`、`https://specie.chaoxing.com/apis/message/updateMessageReadStatus?`、`https://learn.chaoxing.com/apis/user/getUserValidateMsgs?`。

## 8. 另外两条「到课」链路（此前报告只提了前缀，这里补全）

| 二维码前缀 | 处理类 | 性质 |
|---|---|---|
| `SIGNIN:` | `com.chaoxing.mobile.s.` → 通道 B `newsign/studentSign` | 学生扫码签到 |
| `INTELLIGENT_CLASSROOM:` | `com.chaoxing.mobile.intelligentclassroom.ConfirmScreenActivity`（另有 `intelligentclassroomfeitu.ConfirmScreenActivity`） | **智慧教室大屏到课确认**，与签到并列的第二条"我到教室了"链路 |
| 座位预约码 | `com.chaoxing.reserveseat.ui.QRcodeVerifyActivity` | 图书馆/自习室座位核销，非考勤但同样"到现场" |

## 9. 一键组合

```bash
# 巡检（不需要确认，也不会误提交）
python3 scripts/autosign.py --uid <puid> --cookie-file cookies.txt --list-only --want-type --stealth

# 常驻巡检 + 自动交（二维码类自动跳过，交给 qr_sign_remote.py）
python3 scripts/autosign.py --uid <puid> --cookie-file cookies.txt --name <姓名> --fid <fid> \
        --loop --interval 30 --stealth

# 二维码：看屏中继（0.16s 解出 → 直签）
python3 scripts/qr_relay.py --source screen --submit --uid <puid> --cookie-file cookies.txt --name <姓名> --stealth
```

## 10. 可行度与代价

| 接口族 | 需要 | 风险 | 备注 |
|---|---|---|---|
| 视频进度上报 | 课程数据里的 reportUrl（H5/接口可取）+ enc | 中：防拖拽校验 | 慢速增量最安全 |
| 签到四条通道 | cookie + uid（+ phoneId / enc） | 低-中 | 见 `docs/签到类型全表.md` |
| noFinishActiveCount | 仅 cookie | 极低 | 只读 |
| 作业/考试跳转 | cookie | 低 | 跳转只读；提交在 H5 |
| 讨论/投票 | cookie + H5 参数 | 中 | 参数在 H5 侧 |
| 直播 | cookie | 低 | 只读为主 |
| 成绩 | cookie | 极低 | 只读 |
| 智能教室确认 | 大屏二维码内容 | 中 | 与签到同级的到课证据 |
