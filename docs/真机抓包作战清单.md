| # | 请求 | 关键点 |
|---|---|---|
| 1 | POST pan-yz.chaoxing.com/upload?_from=mobilelearn&_token=…（multipart file/puid） | 响应里的 objectId / resid / data.encryptedId |

## 三条路线（按顺序试）

### S1 chrome://inspect 看 WebView ★ 首选
不需要 root、不需要证书、不用改网络。拍照签到的提交本来就是 WebView 里的 H5 发的，只要 App 没关 WebView 调试，DevTools 里能直接拿到 PHOTO_RESULT、deviceCode、cookie、objectId，以及 /pptSign/stuSignajax 的 Copy as cURL。
取证片段：scripts/device/webview_console.js（Console 里整段粘贴）。
看不到 WebView 属正常（App 未调 setWebContentsDebuggingEnabled）→ 走 S2 / S3。

### S2 USB 代理抓包

    bash scripts/device/mitm_capture.sh start   # adb reverse + 设备全局 http_proxy -> 本机 mitmproxy
    bash scripts/device/mitm_capture.sh stop    # 必须执行，否则手机像断网

Android 7+ 的 App 默认不信任用户 CA：不能 root 时 WebView 的 H5 请求可解、原生上传会 TLS 失败；能 root 就把 CA 装进系统证书。

### S3 root + frida（最完整）

    adb push frida-server-17.26.3-android-arm64 /data/local/tmp/fsd && adb shell chmod 755 /data/local/tmp/fsd
    adb shell 'setsid /data/local/tmp/fsd -D </dev/null >/data/local/tmp/fsd.log 2>&1 &'
    frida -U -f com.chaoxing.mobile -l scripts/hide_env.js -l scripts/device/frida_android_capture.js

frida_android_capture.js 会打印 okhttp 请求/头、multipart 字段、响应体、WebView 加载、云盘上传配置、人脸桥 signToken/faceEnc、Cookie 写入，并强制打开 WebView 远程调试。
必须与 scripts/hide_env.js 同载：梆梆会检测 frida 自毁（模拟器实测 0.0s 被杀）。

## 环境自检

## 要回收的六样
1. /pptSign/stuSignajax 的完整请求头 + body + 响应原文
2. PHOTO_RESULT 原值
3. deviceCode、fid、name、uid 实际值
4. Cookie 全量（document.cookie）
5. 上传响应 JSON（objectId/resid/encryptedId/crc）
6. 预签页响应 HTML（含 enc 隐藏域）
