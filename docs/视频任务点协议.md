# 视频任务点（播放进度上报）协议

> 来源：解壳 dex 反编译 —— `com.chaoxing.mobile.player.course.viewmodel.CourseViewModel->S`、
> `com.chaoxing.mobile.player.course.model.b`（发送与响应）、`com.chaoxing.mobile.player.course.model.d->c`（字段解析）、
> `com.chaoxing.mobile.player.course.CoursePlayerFragment->Ua`（判定落地）。
> 定稿时的样本：framework 解壳后的 11 个 dex（sha256 见 `evidence/dexes.sha256`）。

## 1. 一句话链路

```
knowledge/cards  →  ananas/job（拿 reportUrl / objectId / duration / rt）  →  {reportUrl}?…&enc=<MD5>
     章节卡片            视频任务信息                                        每 reportTimeInterval 秒上报一次
```

三条 URL 全部可静态确定，**只有 `reportUrl` 是服务端下发的**（它是绝对 URL，客户端拿到后直接补查询串）。

| 步骤 | 方法与主机 | 路径 |
|---|---|---|
| 章节卡片 | GET `mooc1-api.chaoxing.com` | `knowledge/cards?clazzid=%s&courseid=%s&knowledgeid=%s&num=%s&isPhone=%d&control=%s&cpi=%s` |
| 视频任务 | GET `mooc1-api.chaoxing.com` | `ananas/job?jobid=%s&knowledgeid=%s&courseid=%s&clazzid=%s&jtoken=%s` |
| 进度上报 | GET `{reportUrl}`（服务端给） | `?otherInfo=&playingTime=&duration=&akid=null&jobid=&clipTime=&clazzId=&objectId=&userid=&isdrag=&enc=&rt=&dtype=Video&view=json` |

## 2. 上报的字符串模板

客户端常量（`com.chaoxing.mobile.player.course.model.a->a`，与 `CourseViewModel->S` 内联的同一份）：

```
?otherInfo=%s&playingTime=%s&duration=%d&akid=null&jobid=%s&clipTime=%s
&clazzId=%s&objectId=%s&userid=%s&isdrag=%d&enc=%s&rt=%s&dtype=Video&view=json
```

| 参数 | 来源 | 说明 |
|---|---|---|
| `otherInfo` | `CourseVideo.otherInfo` | 服务端下发，常为空串 |
| `playingTime` | 播放位置 | **秒**；`isdrag=1` 时是 `"拖动起点秒-拖动终点秒"` |
| `duration` | `CourseVideo.duration` | 秒（未乘 1000） |
| `jobid` | `CourseVideo.jobid` | 为空时客户端给空串 |
| `clipTime` | 见下 | 有剪辑段时 `"vbegin_vend"`，否则 `"0_<duration>"` |
| `clazzId` / `objectId` / `userid` | 班级号 / 视频对象号 / puid | puid 来自本地账号 |
| `isdrag` | 0/1 | 1 = 拖动触发，0 = 周期心跳 |
| `enc` | 见第 3 节 | MD5 |
| `rt` | `CourseVideo.rt`（`optDouble("rt")`） | 服务端下发的小数，客户端原样回传 |

`clipTime` 规则（`S` 方法里就是这一层 if）：

```
vbegin >= 0 且 vend > 0  →  "<vbegin>_<vend>"
否则                     →  "0_<duration>"
```

## 3. enc 公式（关键突破：纯本地 MD5）

```
plain = "[" + clazzId + "][" + puid + "][" + jobid + "][" + objectId + "]"
      + "[" + playing_sec*1000 + "]"
      + "[d_yHJ!$pdA~5]"
      + "[" + duration*1000 + "]"
      + "[" + clipTime + "]"
enc   = md5_hex(plain)
```

三个容易踩的坑：

1. **单位不一致**：查询串里的 `playingTime` 是秒，enc 里的 playingTime 是**秒乘 1000**；`duration` 同理（查询串秒，enc 毫秒）。
2. **秒级取整**：客户端先 `(playing_ms / 1000)` 做整数除法，再 `*1000`，所以 enc 里的 playingTime 一定是 1000 的整数倍 —— 伪造时不要传任意毫秒。
3. **盐**：`CourseViewModel->S` 里紧邻分隔符的那个短常量（长度 12）。脚本默认从本地 smali 派生（`--selftest` 会打印长度与 sha1 供比对），也可用 `--salt-smali` / `--salt-apk` 现场取。

## 4. 服务端判定（这一层才是风控所在）

发送走 retrofit（`model.b.o` / `b.g`），基础域 `gc.b.d = https://mooc1-api.chaoxing.com/`，响应体被 gson 反序列化成 `CourseDotRes`：

| 字段 | 含义 |
|---|---|
| `result` | 1 = 成功；203 = 成功但服务端有话说；0 = 失败 |
| `rollbackPoint` | 默认 -1；≥0 时是**服务端认可的可信进度（秒）** |
| `rollbackStatus` | 是否要求回退 |
| `errorMsg` | 失败原因（客户端直接展示） |

客户端的落地行为（`CoursePlayerFragment->Ua`）：

- `result == 1` → 打 `dot_finish_success`，进度照常前进。
- `result == 203` → 打 `dot_finish_success`；**若 `rollbackStatus && rollbackPoint >= 0`，把播放位置拉回 `rollbackPoint` 秒**（`rollbackPoint == 0` 时拉回 1 毫秒，等于从头）。这是视频任务的反挂机手段：不是拒绝上报，而是把你按回它记录的进度。
- `result == 0` → 打 `dot_finish_error_`，界面显示重试容器。

HTTP 层另有约定：非 2xx 一律按失败处理；**HTTP 203 被单独当作"成功但可能回退"**。
客户端还把每次上报的结果写进自己的日志通道（`dot_commit_server_url`、`dot_commit_finish_`、`dot_finish_success_`、`dot_finish_error_`），这些日志本身也是一种服务端/取证可见的痕迹。

## 5. 静态与运行时的差异（本轮修正）

| 项 | 静态初版的说法 | 本轮实证 |
|---|---|---|
| enc | 「盐 + 参数拼接，细节待定」 | 明文模板与单位换算已完全确定（见第 3 节） |
| 上报间隔 | 未知 | `CourseVideo.reportTimeInterval`，缺省 60 秒 |
| 服务端反馈 | 未涉及 | `CourseDotRes` 四字段；203 + rollbackPoint 会回退播放位置 |
| 倍速 | 未知 | `doubleSpeed` 为字符串，不等于 `"0"` 即允许倍速（`CourseViewModel->k`） |
| 防拖动 | 未知 | `fastforward` 布尔位（服务端下发），置真时客户端禁拖 |
| 人脸 | 仅签到链路 | 视频还有 `faceRecConfig` / `captureConfig` 两个配置位（抽查截图/人脸），是否启用由服务端下发 |

## 6. 未验证项（需要一次真机抓包）

1. **`reportUrl` 的真实形状**：它是服务端字段，静态里没有。实测 `mooc1.chaoxing.com/multimedia/log/...` 各变体返回 404，`/multimedia/log`（不带参数）返回网关 403 —— 只能靠 `frida_video_hook.js` 抓一次真值。
2. **`rt` 的语义**：客户端只做 `optDouble("rt")` 原样回传，是否是"服务端随机挑战/播放速率校验"需要抓两次对比。
3. **203 的触发条件**：是上报过密、进度跳跃过大，还是与服务端记录的进度不一致 —— 需要连续两次不同 pace 触发。
4. **`playingTime` 与真实时间的比对**：服务端是否用 `rt` 或时间戳做换算（即"快进上报"能不能被识别）。
5. **视频人脸抽查**：`faceRecConfig` 非空时是否会在播放中弹人脸 —— 若会，视频链路同样要按签到人脸的四个层次处理。

## 7. 命令速查

```bash
# 自检（盐派生 + 公式 + URL 结构 + 判定解析，不联网）
python3 scripts/video_task.py --selftest

# 列出某节课的视频任务（要 cookie）
python3 scripts/video_task.py --uid <puid> --cookie-file ck.txt \
    --course-id <C> --clazz-id <K> --knowledge-id <N> --list --dump job_cards.json

# 干跑：只打印 URL 与 enc，不发请求
python3 scripts/video_task.py --uid <puid> --job-json job.json --dry-run --limit 3

# 真正上报（默认 60 秒一格、与真实播放同速；--pace jitter 走拟人抖动）
python3 scripts/video_task.py --uid <puid> --cookie-file ck.txt --job-json job.json \
    --stealth --speed 1.0 --pace real --audit video_audit.jsonl

# 抓真值（AVD/真机）
frida -U -f com.chaoxing.mobile -l scripts/frida_video_hook.js --no-pause
adb shell cat /data/local/tmp/cx_video_cap.jsonl > cap.jsonl

# 用抓到的明文/密文对验证本地公式
python3 scripts/video_task.py --verify-capture cap.jsonl
```

## 8. 边界

- 脚本只处理使用者自己账号的课程任务点；仓库内无 cookie、无账号。
- 默认 `--pace real`（按真实播放节奏上报）。`--speed >1` 或 `--pace fast` 是**会触发服务端回退**的用法，脚本会在收到 `rollbackPoint` 时打印警告，`--stop-on-rollback` 可以直接停手。
- 第 6 节的五项未验证项在完成真机抓包前，不要把本文的公式当作"已通过服务端校验"的结论。
