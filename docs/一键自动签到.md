# 一键自动签到流水线（教师侧取码 → 学生侧提交）

> 目标：把「教师侧当前二维码内容」到「学生侧签到成功」之间的**全部中间过程**粘成一条命令。
> 脚本：`scripts/cx_pipeline.py`（624 行，已 py_compile，阶段 ②/③/④ 均已实测；①③的教师侧待第一次真实教师 cookie 跑）
> 样本：学习通 6.7.8（sha256 bd020876…2fa8cb14），包 com.chaoxing.mobile，梆梆 SecNeo 加固

---

## 0. 一句话

教师 cookie 进 → 自动枚举班级 → 自动定位进行中的二维码签到 → 自动从教师页取当前 `enc` →
用学生 cookie 自动提交 → 判定响应纯文本 `success`；全程一条命令，失败自动落盘诊断。

```
python3 scripts/cx_pipeline.py --mode watch \
    --tch-cookie-file ck_tch.txt --stu-cookie-file ck.txt --uid <学生puid> \
    --course <courseId> --class <classId> --stop-on-success --verbose
```

## 1. 为什么必须这么搭（三条实测事实）

| 事实 | 证据 | 后果 |
|---|---|---|
| 学生端页面**造不出** enc | `out/preSign_4000180737792.html`：`var aidInEwm=""; var enc="";`，只有 `CLIENT_BARCODE_SCANNER` 回调里 `enc = getUrlParam(msg,"enc")` | 学生侧任何"自造 enc / 续期"的路都断了 |
| 服务端**不下发** enc | `newsign/signDetail` 带 msg=二维码原文 / SIGNIN 串 / signCode / 不带 msg，四种返回 69 字段**完全一致**，无 enc 字段 | 扫描动作本身换不来新 enc |
| 错误文案是**分类**的 | clone 活动(id 4000180737792,status=1) → `签到失败，请重新扫描。`；父活动(4000180737791,status=0) → `此次签到未开始`；伪 enc test123 与 clone 同文案 | 我们的失败点**只在 enc**，不在参数/会话/流程 |

社区同协议实现（cxOrz/chaoxing-signin `functions/qrcode.ts`、HEDBS/chaoxing-sign `chaoxing_sign.py:151`、博客 log.1k.ink）里
`enc` 全是**入参**，都不生成、不续期。→ 唯一能自动拿到"当前有效 enc"的入口，就是**教师侧页面**。

## 2. 流水线四段

| 阶段 | 接口 | 产出 | 降级 |
|---|---|---|---|
| ① 教师班级枚举 | `mooc1-api.chaoxing.com/mycourse/backclazzdata?view=json&getTchClazzType=1&mcode=<puid>` | [courseId, classId, 角色] | 失败则用 `--course/--class` 手给 |
| ② 活动定位 | `ppt/activeAPI/taskactivelist?courseId&classId&uid` + `courseactivelist?puid&status=1` | 进行中的二维码签到 activeId（自动过滤 groupList 汇总行，只留 10 位以上数字 id） | 失败则用 `--aid` 手给 |
| ③ 教师侧取 enc | `pptSign/gotasksign?...&isTeacherViewOpen=1` → `newsign/preSign?...&isTeacherViewOpen=1` → `sign/produceSignView?tid&uid&appType` | `{enc, aid, c}` 候选，**带评分排序** | 页面正则失败则自动下图片（viewPicPath/teachingPlan/ewm*.png、data:image base64）→ cv2 多尺度解码 |
| ④ 学生侧提交 | `mobilelearn.chaoxing.com/pptSign/stuSignajax?enc=<enc>&name=&activeId=<aid>&uid=<puid>&...&appType=15` | 响应纯文本 `success`/`success2` = 成功 | — |

③ 的抽取能力体现在两路并存：**HTML 正则**（`widget/sign/e?…`、`[?&]enc=`、`enc:"…"`、`signCode`）
＋**二维码图片解码**（`qr_relay._decode_cv2_multi`：原图/灰度 ×1/2/3/4× 放大 ×反色，detectAndDecodeMulti → detectAndDecode）。
候选打分：带 id 的二维码链接 +4、aid 命中 +3、16–64 位十六进制 +2、模板串（`{{…}}`）−6；明显占位（`xxx`/`null`/`undefined`/单字符重复）在抽取层就丢掉。

## 3. 快速开始

**A. 直接给教师 cookie（最省事）**
浏览器登录 learn.chaoxing.com → F12 → Network → 任一请求 → 复制 Cookie 整条 → 存成 `ck_tch.txt`（单行）。

**B. 用教师账号自动登录（推荐，能自动重登）**
```
export CX_TCH_PHONE=1xxxxxxxxxx
export CX_TCH_PASS=********        # 不进 argv、不落日志
python3 scripts/cx_pipeline.py --mode watch --tch-login \
    --tch-cookie-file ck_tch.txt --stu-cookie-file ck.txt --uid <学生puid> --stop-on-success --verbose
```
cookie 失效会被自动识别（响应里出现 passport2 / 请登录）并**当场重登一次**再继续。
登录契约：`POST passport2.chaoxing.com/fanyalogin`，`uname/password` 为 AES-CBC(Pkcs7, iv=key, key=transferKey) 的 Base64，
返回的 `url` 字段必须 `unquote` 后再跟随（`scripts/cx_login.py`）。

**C. 已经有 enc，只要提交**
```
python3 scripts/cx_pipeline.py --mode submit-url --qr "<widget/sign/e?id=..&c=..&enc=..>" \
    --stu-cookie-file ck.txt --uid <学生puid>
```

## 4. 模式速查

| 模式 | 作用 | 典型命令补充参数 |
|---|---|---|
| `discover` | 只枚举：教师班级 / 活跃活动 / enc 候选，不提交 | `--aid` 可指定单活动深挖 |
| `once` | 取一次 enc 就提交一次 | `--enc --aid` 可跳过教师侧 |
| `watch` | 轮询（默认），活动或 enc 变化才提交 | `--interval 10 --rounds --max-submits --stop-on-success` |
| `submit-url` | 直接提交一段二维码内容 | `--qr` |

其他开关：`--want-type 2`（目标活动类型，默认二维码签到）、`--dry-run`（只到取 enc）、`--ua-mode browser|app|h5`（默认 h5＝App WebView UA+`X-Requested-With`）、`--quiet-hours 1-7`（凌晨静默，`none` 关闭）、`--dump-dir`、`--log`。

## 5. 诊断与产物

- `out/tch_probe/rNN_<tag>_<n>.html`：教师侧每个可疑响应都存原文（文件头两行注释写了请求 URL 与最终跳转 URL）。
- `out/pipeline.jsonl`：每轮一行，字段 `t/round/event/enc(前16位)/aid/src/ok/msg`；`event ∈ no_enc|enc_found|submit|risk|error`。
- 取不到 enc 时**不静默**：打印 `第 N 轮未取到 enc 候选（诊断文件见 out/tch_probe/）`，直接看落盘 HTML 就能定位是「换了接口」还是「页面结构变了」。

## 6. 已知边界与纪律

- **不保证**教师页永远带 enc：梆梆壳只护客户端，服务端页面结构一变就要重抽；脚本以"落盘原文 + 双路抽取 + 评分"抗第一轮变化，不抗大改。
- 位置类签到（`activeType=5`）提交时必须带 `ifTiJiao=1`，拍照类（`activeType=1`）要先上传拿 `objectId`——本流水线只覆盖二维码/普通类，其余走 `autosign.py`。
- 风控/限速走 `stealth_session.RiskGuard + RateGovernor + RiskHalt/RiskCooldown`，默认 8 s 间隔、每小时 6 次、每天 30 次写入上限，凌晨 1–7 点静默；触发即 `[STOP]`/`[WAIT]`。
- **模拟器路线已实测排除**：App 在 android-29 / android-30 模拟器上启动约 3 s 原生自杀（SIGSEGV pc=0x3d8/0x3dc，sp=lr=0），去 root、停 frida、全新安装均不变；详见 `docs/扫码签到实测.md` 第 10 章。逆向数据（`Lf3/c;->F/J/L/N`）证实是 App 自带模拟器探测 + 壳侧自检，用它取 enc 没有增量。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `无 enc 候选` 且 HTML 落盘为登录页 | 教师 cookie 失效 | 换 `ck_tch.txt`，或用 `--tch-login` |
| 活动列表为空 | 教师账号不在这门课的班级里 / 用错了 puid | `--mode discover` 看班级枚举结果，必要时 `--course/--class` 手给 |
| 有 enc 但 `签到失败，请重新扫描。` | enc 过期（c 每 ~10 s 轮换、isOver=1 表示展示会话已关） | 把 `--interval` 调到 3–5 s；或确认教师端签到页正被打开（`isOver=0`） |
| `此次签到未开始` | 提交到了父活动（`parentId`）而不是 clone | 用 `signDetail` 返回的 `activePrimaryId`（clone）而非 parentId |
| `请先登录再进行签到` | 学生 cookie 没带 / 过期 | 重新登录学生账号写 `ck.txt` |

## 9. ★ 权威取码接口 `/v2/apis/sign/refreshQRCode`（本轮突破）

教师签到页（`pptSign/gotasksign?...&isTeacherViewOpen=1` / `newsign/preSign?...&isTeacherViewOpen=1`，113,262 B，落盘 `out/tchpages/gotasksign.html`）JS 原文：

```js
var ewnEnc="", ewnCode="";
function updateEwm(){ jQuery.ajax({type:"get", url:"/v2/apis/sign/refreshQRCode",
    data:{activeId:activeId, time:new Date().getTime()},

      if(ewnCode!=sc){ ewnCode=sc; dealEwnImage(); } } }});}
```

| 调用（教师 cookie） | 返回 |
|---|---|
| `GET /v2/apis/sign/refreshQRCode?activeId=4000180737792&time=<ms>` | `{"result":1,"msg":"success","data":{"refresh":1,"enc":"CE5C7F65C3D8CCB512FE71A91CE72B13","signCode":"927438"}}` |

## 10. 人脸闸门（`checkFace_<enc2>` → `/pptSign/check-face-result`）

学生端页面（`out/preSign_4000180737792.html`）原文链：

1. 服务端返回 `checkFace_<enc2>` → `enc2=res.substring(10)` → `url += "&enc2="+enc2` → `checkFace(url)`。
2. `function checkFace(url){ CHECK_FACE_SIGN_URL=url; jsBridge.postNotification("CLIENT_FACE_RECOGNITION_BLINK",{funTag:3,funData:{ignoreFaceId:ignoreFaceId}}); }`
3. App 回调校验：`LiveDetectionStatus!=1`→“活体检测失败”；`collectStatus!=1`→退出；`!currentFaceId`→“人脸采集失败”。
4. 通过后 `GET /pptSign/check-face-result?DB_STRATEGY=PRIMARY_KEY&STRATEGY_PARA=activeId&activeId=<aid>&faceResult=<JSON>`，`faceResult` 九字段 = `{currentFaceId, LiveDetectionStatus, collectStatus, cxcid, cxtime, recogType, sessionId, SenseDetectionStatus, signToken}`。
5. 最终 `POST /pptSign/stuSignajax` 追加 `enc2` + `currentFaceId` + `ifCFP=1` + `courseId` + `faceEnc`（= check-face-result 返回的 enc）+ `faceCode` + `faceEncAid` + `locationResult`；成功仍是 `success`/`success2`。

**探针（学生 cookie，本机实测）**：

| 请求 | 响应 |
|---|---|
| `faceResult={}` | `{"status":0,"code":"CFR001"}` |
| `faceResult={currentFaceId:"FAKEFACEID123",LiveDetectionStatus:1,… 九字段全伪}` | `{"status":0,"code":"CFR007"}` |

→ 服务端**逐字段校验**，伪造字段拿不到 `faceEnc`；`signToken/cxcid/sessionId/currentFaceId` 只能由真实采集会话产生。相关实现类：`Lcom/chaoxing/mobile/webapp/jsprotocal/exam/FaceRecognitionExecutor;->Y`（组装并回传九个字段）、`Lcom/chaoxing/mobile/exam/collect/FaceCollectManager;->s0`、`Lcom/chaoxing/mobile/webapp/jsprotocal/security/b;->J/K`（signToken 解析，含日志串 `signToken json error:`）。

## 11. 作用域白名单（教师账号硬约束）

- 常量：`ALLOW_COURSE="269282723"`、`ALLOW_CLASS="159926750"`、`ALLOW_ANY=False`；`class ScopeViolation(SystemExit)` + `guard_scope(course,clazz,what)`，**联网前拦截**。
- CLI：`--allow-course`（默认 269282723）、`--allow-class`（默认 159926750）、`--allow-any-class`（默认关）。
- 实测：`--course 999999 --class 888888` → `[scope] 拒绝越界：命令行参数 course=999999 不在白名单 269282723（只允许计算机二级测试班）`；`classes()` 按白名单过滤（10 个班只请求 1 个）。
- 踩坑：argparse 里用模块常量当默认值 → `SyntaxError: name 'ALLOW_COURSE' is used prior to global declaration`；`global` 必须是 `main()` 第一行。
