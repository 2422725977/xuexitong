## 0. 结论速览

1. **壳**：目标被梆梆安全（SecNeo / Bangcle）加固。classes.dex 名义 98,377,912 B，真实 dex 内容只到偏移约 24,728（17 个类：12 个 Lcom/alibaba/android/arouter/routes/* + 5 个 Lcom/secneo/apkwrapper/{AP,AW,CP,H,a}），其后 ~98 MB 是加密载荷。
2. **纯静态解壳本机不可行**（§3 有失败证据：2570 个 zlib 候选 0 成功、单字节 XOR 无 dex magic、末 8 MB 是随机数据）。签到代码里的参数拼装 / 加密 / 签名逻辑**在加密段内，静态拿不到**。
3. **但情报面并不空**：载荷字符串池（570,502 条可打印串）泄漏出签到模块 **18 个类描述符**、考勤统计 **735 个 office 类**、蓝牙签到 **27 个 beacon 类**、以及 **6 条签到核心接口**（含学生提交端点 `newsign/studentSign?rcode=%s&uid=%s`）、全部签到文案与入口 Activity。→ §2、§6
4. **下一步只差“把代码取出来”**：A 运行时 dex dump（最直接）／B Frida 去证书固定 + 抓包（不反编译也能复现签到请求）／C 直接按接口复现（参数由 B 补齐）。→ §5

## 3. 为什么静态解壳在这里走不通（失败证据留档）

| 尝试 | 结果 |
|---|---|
| 2,570 个 zlib 头候选逐个 `zlib.decompressobj`（wbits=15 与 -15） | 成功 0（`0x78` 是巧合字节） |
| 10 个区域头 × 256 个单字节 XOR 键 | 无 `dex\n035` 命中 |
| 内嵌 `PK\x03\x04`（14871863 / 18191542 / 29333864） | 本地头字段解析出垃圾文件名与荒诞长度 → 误报 |
| 末 8 MB 结构分析 | 523,044 个不同 16 字节块（8 MB 内）→ 真随机/真加密 |
| 结论 | 载荷是密码学加密（密钥在 `libDexHelper.so`/`libdexjni.so` 内或运行时获取），**必须运行时 dump** |

**关键不可达判据**：`ifTiJiao` 0 命中、`clientip` 0 命中、`activeId` 仅在载荷内 9 处、`signType` 2 处 —— 签到请求的参数字面量整段位于加密代码里，纯静态无法还原请求体。

## 5. 行动路线

### 路线 A（推荐）：运行时 dex dump，拿到真代码

设备：Android 8–13 真机或模拟器，root 或可跑 frida-server。

`@
# 1) 本机装工具（当前机器无 frida/adb）
brew install --cask android-platform-tools
/opt/anaconda3/bin/pip install frida frida-tools frida-dexdump

# 2) 设备侧
adb push frida-server-16.x.x-android-arm64 /data/local/tmp/frida-server
adb shell "su -c 'chmod 755 /data/local/tmp/frida-server && /data/local/tmp/frida-server &'"

# 3) 启动即 dump（梆梆壳在 attach 早期解密 dex）
/opt/anaconda3/bin/frida-dexdump -U -f com.chaoxing.mobile -o chaoxing/out/dump --sleep 10

# 4) 对 dump 出的每个 dex 跑 droidasc（真代码一到手，本机工具链即通）
/opt/anaconda3/bin/droidasc chaoxing/out/dump/classes.dex listclass --prefix com.chaoxing.mobile.sign -o chaoxing/out/dumped_sign_classes.txt
/opt/anaconda3/bin/droidasc chaoxing/out/dump/classes.dex getclass 'Lcom/chaoxing/mobile/sign/ui/SignInfoActivity;' -o chaoxing/out/SignInfoActivity.java
/opt/anaconda3/bin/droidasc chaoxing/out/dump/classes.dex findrefs string 'newsign/studentSign' -o chaoxing/out/refs_studentSign.txt
`@

若 frida-dexdump 被壳检测挡住：换 `FRIDA-DEXDump` 的 spawn 模式/`frida -U -f com.chaoxing.mobile -l hook_open.js` 拦 `open`/`mmap` 落盘 dex，或先 hook `libDexHelper.so` 的 `JNI_OnLoad` 相关导出再看时机。

### 路线 B：Frida 去证书固定 + 抓包（不需要反编译）

`@
# 抓包
brew install mitmproxy && mitmproxy -p 8080            # 手机代理指向本机:8080
# 系统级 CA（Android 7+ 需 root）
adb push mitmproxy-ca-cert.pem /data/local/tmp/ && adb shell "su -c 'mount -o rw,remount / && cp /data/local/tmp/mitmproxy-ca-cert.pem /system/etc/security/cacerts/$(openssl x509 -inform PEM -subject_hash_old -in mitmproxy-ca-cert.pem | head -1).0'"

# 去固定（学习通含 libcipherdb.so / 自研加密，需同时 hook 加密入口）
frida -U -f com.chaoxing.mobile -l ssl_pinning_bypass.js -l hook_cipher.js

# 触发签到：进入签到页 → 扫码/定位 → 观察
#   请求：POST https://mobilelearn.chaoxing.com/newsign/studentSign?rcode=…&uid=…
#   记录：完整 URL + body + header + sign 家族参数（对应 §4）
`@

### 路线 C：纯 HTTP 复现签到（最省事的“效果验证”）

用路线 B 抓到的会话复现：

`@
GET  https://mobilelearn.chaoxing.com/pptSign/gotasksign?courseId=COURSE_ID&classId=CLASS_ID&puid=UID&source=1&showSaveBtn=0&hideBeginButton=1&isTeachingCalendar=1

## 7. 一句话总结

学习通 6.7.8 的签到模块在**加固壳后**：静态只能拿到「类骨架 + 6 条核心接口 + 文案 + 入口」，签名与参数在加密段（若要求得真代码，走路线 A 的运行时 dump；若只想复现签到行为，走路线 B 抓包 + 路线 C 复现，本报告的接口表已经够用）。
